# Contributing

## Before changing code

1. Read [AGENTS.md](AGENTS.md) and the instruction file for the assigned directory.
2. Inspect current code and tests for existing patterns.
3. Confirm the allocated scope and review overlapping work.
4. Create a focused branch or worktree.

## Development setup

See [docs/engineering/development-setup.md](docs/engineering/development-setup.md).

## Pull requests

- Keep changes focused and avoid unrelated edits.
- Use the [pull request template](.github/PULL_REQUEST_TEMPLATE.md).
- Document architectural decisions under [docs/decisions/](docs/decisions/).
- Include relevant tests and checks.
- Call out security, multi-tenancy, and deployment implications explicitly.

## Completion checklist

- Relevant checks pass.
- Files outside the assigned scope remain unchanged.
- No secrets or generated artifacts are committed.
- Changed files, decisions, unresolved issues, and verification are reported.
